# PAD 文件传输记录设计与维护

## 1. 产品目标

传输记录不是文件系统快照，而是用户已经执行过的传输动作。用户可以看清上次从哪里传到哪里，并对仍然存在的源文件一键再次执行同一路径传输。

当前交付版本：`1.4.57+162`。

### PAD本地文件分享（1.4.57）

左侧PAD本地列表中的所有普通文件显示“分享”，Android按MIME类型只列出支持该文件的应用。文件夹和右侧远端文件不显示分享；远端文件必须先传回PAD。分享使用私有FileProvider的单URI临时读权限，不共享整个目录。调起系统分享面板后文件传输辅助窗口允许结束，返回远控页后点击独立“文件”按钮重新打开。

### PAD本地APK安装（1.4.56）

左侧PAD本地列表中的`.apk`普通文件额外显示“安装”。选择后先在原生层复核文件和APK结构，再交给Android系统安装器；右侧远端列表不显示该操作，必须先传回PAD。安装动作不改变原有选择、传输、删除和记录逻辑，也不把APK自动登记为可删除文件。

## 1.1 1.4.55 双栏传输与安全删除边界

- PAD与对方目录在同一窗口左右并列；每次成功读取目录和关闭页面都会清空旧选择，禁止把上一目录不可见的选中项带入新任务。
- option `kemi-received-local-files-v1`只登记“对方 → PAD”且最终成功的目标。原PAD文件、失败/跳过的任务、PAD发送到对方的内容均不登记。
- 已接收文件仅在路径、文件类型、大小及可获得的mtime仍匹配时可删除；用户修改过的文件自动失去授权。
- 已接收文件夹登记根路径与目录类型。根目录mtime会随子项到达变化，因此不比较mtime；删除入口只出现在精确登记的根目录，执行递归删除。成功后`forgetTree`移除根和全部子项记录，防止同路径重建后误删。
- 文件夹授权的明确语义：删除收到的根目录会递归删除其中当前全部内容，包括用户后来放入该目录的新文件。该行为不扩展到其父目录、PAD原有目录或对方文件系统。
- 对方传PAD时，目录大小先递归汇总，再通过Android `StatFs`读取目标卷可用字节；总量大于可用空间50%时禁止，等于50%允许。测量失败时拒绝。PAD传桌面和Mac目标按需求跳过此限制。

## 2. 界面规则

- 文件页右上角显示“记录”；有记录时显示项目数。
- 进入记录页后，右上角固定改为箭头加“返回文件”。列表顶部和空状态都提示如何返回，Android系统返回键也优先回到文件页。
- 记录按传输方向、源目录、目标目录归组。组头显示“PAD → 对方”或“对方 → PAD”以及两端完整目录。
- 每个文件/文件夹一行，显示最近状态、累计传输次数、大小和最近时间。
- 每行固定提供“再次传输”；右侧叉号只删除记录，不删除源文件或目标文件。
- 相同方向、相同源目录、相同目标目录中的同一完整源路径只保留一项；再次传输只更新次数和时间。

## 3. 数据与生命周期

实现文件：

- `flutter/lib/models/transfer_history_model.dart`
- `flutter/lib/models/file_model.dart`
- `flutter/lib/mobile/pages/file_manager_page.dart`

记录保存在对应peer的Flutter option：

```text
kemi-transfer-history-v1
```

记录不设置自动过期或数量淘汰：只要用户不点击删除记录、没有清除App数据或卸载App，关掉页面、结束进程和PAD重新开机后都必须保留。Windows路径在生成去重键时统一斜杠并忽略大小写；Unix路径保持大小写敏感。记录只保存在本机，不上传服务器。

关键时序：

```text
用户确认粘贴
  → registerTransfer：先增加次数、状态设为传输中并同步持久化
  → sendFiles：创建真实传输任务
  → onJobCreated：把任务ID绑定到已经存在的记录项
  → JobController：完成或失败时更新记录状态并再次持久化
```

必须先记录再分发任务。若等任务回调后才创建记录，小文件可能已经完成，任务状态和记录绑定会发生竞态，表现为“传完了但记录仍为空”。

## 4. 再次传输与错误融合

点击“再次传输”后按以下顺序执行：

1. 实时读取目标目录；不存在或无权限时，原行显示“目标文件夹不存在或无法访问”。
2. 实时读取源目录，并按完整源路径寻找原项目；找不到时，原行显示“源文件不存在”。
3. 两端都有效才重新创建`SelectedItems`并进入正常发送流程。
4. 校验和发起期间按钮显示圆形进度并禁止重复点击。
5. 传输任务的完成/失败状态仍由`JobController`回写，错误不另开新页面。

## 5. 验收清单

每次修改后至少验证：

1. PAD → 对方和对方 → PAD各完成一次，记录立即出现。
2. 发送小文件，确认不会因瞬时完成而漏记录。
3. 同路径再次发送，项目不重复，次数递增。
4. 切到记录页，能明显看到“返回文件”和顶部提示；系统返回键也能回来。
5. 强制停止并重开App，记录仍存在。
6. 删除或移动源文件后点“再次传输”，行内提示源文件不存在。
7. 删除或移动目标目录后点“再次传输”，行内提示目标目录不可访问。
8. 点击删除记录，只移除历史项，不触碰任何真实文件。
9. 成功接收文件后可删除；修改大小/mtime后入口消失；PAD原文件始终不可删除。
10. 成功接收文件夹后可递归删除；删除后重建同路径不再可删；对方目录始终不可删除。
11. 传输量等于PAD目标剩余空间一半时允许，大于一半时原位报错；Mac目标不执行该门禁。

定向自动测试共8项，覆盖一半边界、超限、测量失败、文件匹配/修改、文件夹登记/未登记及`forgetTree`清理；`flutter test test/file_transfer_policy_test.dart`已通过。

## 6. 双屏窗口归属（1.4.48+138）

- 在双屏 PAD 的远控画面点击“传输文件”时，文件传输窗口必须出现在远控画面对面的屏幕，不能覆盖远控画面。
- 显示映射为：远控在默认屏 Display 0 时，选择当前开启的非默认屏；远控在任一副屏时，文件窗口回到 Display 0。只有一块可用屏幕时继续使用原有同屏 60% 浮窗，不把单屏设备判为失败。
- 跨屏窗口由 Android `FileTransferActivity` 和独立 FlutterEngine 承载；Flutter 专用入口复用 `FileManagerPage`，文件浏览、传输记录、再次传输和错误提示不复制第二套实现。
- 文件传输拥有独立 FFI Session。打开和关闭文件窗口均不能关闭、替换或重新连接正在显示视频的远控 Session；关闭顺序必须先释放文件模型和文件 FFI，再结束跨屏 Activity。
- 验收至少覆盖两个方向、真实目录浏览、一次真实文件传输、关闭后远控画面继续、单屏回退五项。Android `dumpsys activity activities` 中应看到两个屏幕各自承载独立 Activity，关闭后只移除 `FileTransferActivity`。

## 7. 文件按钮状态与非模态原生窗口（1.4.62+167）

### 7.1 为什么视觉浮窗仍会挡住桌面

旧实现的`FileManagerPage`只把Flutter卡片绘制为屏幕90%×78%，承载它的`FileTransferActivity`仍是1920×1280全屏透明窗口。透明像素并不等于不存在窗口，因此主屏桌面虽然可见，触摸仍先进入KEMI的全屏输入层。

现在`FileTransferActivity`使用独立`FileTransferWindowTheme`，原生Window本身设为显示屏90%×78%、居中、透明、不变暗，并增加`FLAG_NOT_TOUCH_MODAL`。1920×1280真机上的实际窗口属性必须是：

```text
Requested w=1728 h=998
mFrame=[96,93][1824,1091]
flags include NOT_TOUCH_MODAL
```

专用Flutter入口把文件卡片填满这个小窗口，所以卡片外观和可用面积保持不变；窗口外区域由Android直接分发给桌面或其他应用。主屏操作其他应用后，文件Activity允许进入停驻`hidden`，不能抢回前台或继续遮挡输入。

### 7.2 副屏按钮与主屏生命周期

文件窗口状态只允许以下五种：

```text
closed → opening → open → closing → closed
                    ↓
                  hidden  （HOME或主屏切换到其他应用）
```

打开时副屏文件图标为绿色并带半透明绿色背景；`closed/hidden`为白色透明背景；过渡中显示进度环并禁用重复点击。Native主动向MainActivity或RemoteActivity对应的FlutterEngine发送`file_transfer_window_state`，RemotePage启动时再用`get_file_transfer_window_state`补查，不能用本地按钮猜测窗口是否存在。

副屏第二次点击时，Native向文件窗口专用FlutterEngine发送`request_close`；`FileManagerPage`依次执行`model.close()`、独立`FFI.close()`，最后调用`finish_activity`。四秒Native超时只用于Flutter异常时兜底，正常日志必须出现`close_button`再出现`activity_destroyed`。主屏关闭图标走同一顺序，副屏状态自动恢复；不得直接`finishAndRemoveTask()`而跳过传输会话释放。

### 7.3 最小回归

1. 第一次点击副屏“文件”，确认按钮绿色带背景、主屏窗口尺寸正确。
2. 点击窗口外主屏桌面，确认桌面能响应、文件按钮变回白色；再次点击可恢复或重开。
3. 副屏连续点击两次，确认第二次关闭文件会话和Activity，但远控视频不断开。
4. 再次打开后点击主屏关闭图标，确认副屏在不轮询的情况下恢复白色。
5. 关闭后核对没有存活的`FileTransferActivity`和独立文件Session；远程键盘、鼠标左右键保持原行为。
